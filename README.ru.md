# Awesome Astra

**Компактные skills для Codex: нужный контекст, полноценные изменения и проверяемый результат.**

[English](README.md) · [Исследования](RESEARCH.md) · [Как индексирует Cursor](docs/CURSOR_INDEXING.md) · [Замеры](EVALUATION.md)

Два skills вместо огромного промпта и обязательной армии агентов:

| Skill | Назначение |
| --- | --- |
| `astra-code` | Разработка, отладка, рефакторинг, проектирование и ревью. |
| `astra-repo-audit` | Аудит и сокращение лишних инструкций без удаления защитных ограничений. |

В **0.2.0** добавлены локальный индекс кода, безопаснее устроенное обновление skills и сравнение парных замеров. **Ускорение, экономия токенов и рост качества на реальных задачах Astra пока не измерены.** Тесты вспомогательных программ не заменяют такие замеры. Это не заявление о создании AGI и не официальный продукт OpenAI.

## Установка

Нужен Python 3.10+. Для необязательного индекса — Git и SQLite с FTS5. Сторонние Python-пакеты, API-ключи, MCP и hooks не нужны.

```bash
git clone https://github.com/Paffin/Awesome-Astra-.git
cd Awesome-Astra-
python3 tools/validate.py
python3 -m unittest discover -s tests -v
python3 scripts/install.py
```

В названии репозитория действительно есть дефис в конце. Перед запуском прочитай скачанный код; для повторяемой установки закрепи проверенный commit.

По умолчанию устанавливается в `~/.agents/skills`. Только основной skill:

```bash
python3 scripts/install.py --skill astra-code
```

Для отдельного проекта используй `--dest /путь/к/проекту/.agents/skills`. Модель GPT-6 Astra выбирается в самом Codex; установщик не меняет настройки модели и разрешения.

При `--force` сначала готовится полная новая копия, затем заменяется установленный skill. Резервная копия хранится **рядом** с каталогом skills, в `.astra-skill-backups`, поэтому не создаёт ещё один обнаруживаемый skill. Одновременные установки блокируются lock-файлом. После аварийного завершения может потребоваться проверить и удалить оставшийся `.astra-install-*.lock`. Обновление транзакционно для каждого skill отдельно, не для всего набора сразу. Старые бэкапы, оставленные прежней версией внутри каталога skills, автоматически не удаляются.

Можно также попросить `$skill-installer` установить папки `skills/astra-code` и `skills/astra-repo-audit` из этого репозитория. Формат пакета — Agent Plugins, формат отдельных skills — Agent Skills. Публикация на GitHub не означает публикацию в каталоге плагинов.

## Работа

```text
$astra-code исправь гонку в worker и проверь исходную регрессию.
$astra-code проведи ревью текущей ветки относительно main.
$astra-repo-audit проверь AGENTS.md и skills; пока ничего не меняй.
```

Для опечатки не строится карта репозитория. Для сложной задачи подгружается нужный сценарий, а не вся библиотека инструкций. Параллельная работа допускается только при доступных инструментах, независимых задачах и разделении изменяемых файлов.

## Локальный индекс

Из каталога этого проекта:

```bash
python3 skills/astra-code/scripts/repo_index.py --root /путь/к/репозиторию search "invoice retry" --max-bytes 12000
```

Индекс обновляется перед поиском, учитывает удалённые и исключённые файлы и возвращает фрагменты с путём, диапазоном строк и SHA-256. Ограничение задаётся в байтах UTF-8 всего JSON-ответа, **не в токенах модели**.

Это лексический поиск SQLite FTS5 с учётом Python AST и построчным разбиением остальных текстовых файлов. Он не заменяет embeddings, полноценный граф зависимостей или семантический поиск Cursor. Каждый запуск перечитывает допустимые файлы для проверки хешей, но заново разбирает и записывает только изменившиеся.

Данные хранятся локально в метаданных Git отдельно для каждого worktree. Утилита не отправляет код в сеть. Однако передача найденного фрагмента облачной модели остаётся внешней передачей данных; исключения не заменяют корпоративную политику и сканер секретов.

Подробности, ограничения, исключения и очистка кэша: [CURSOR_INDEXING.md](docs/CURSOR_INDEXING.md).

## Проверка эффективности

`tools/compare_runs.py` сравнивает реальные парные замеры: входные, кешированные и выходные токены, время, принятие результата и безопасность. Незавершённая задача не считается улучшением только потому, что стоила дешевле. Формат данных и методика — в [EVALUATION.md](EVALUATION.md).

В наборе 24 сценария проверки поведения. Пока это спецификации испытаний, а не доказательство прохождения их моделью. Оценка размера инструкций также приблизительная и не равна счёту за API.
